# MNIST 숫자 분류 MLP 코드 설명 보고서

## 1. 과제 개요

과제: PyTorch를 이용해 MLP 구성하여 0부터 9까지의 손글씨 숫자 분류기 구현

구현에는 데이터 준비, 학습,검증,테스트 데이터 분리, MLP 구성, 미니배치 학습, 검증에 따른 모델 선택, 최종 테스트 평가 순서로 작동

## 2. 데이터 준비 및 분할

`torchvision.datasets.MNIST`로 공식 MNIST 데이터셋을 불러옴.

`transforms.ToTensor()`는 픽셀 범위를 일반적으로 0~255에서 0~1로 변환하는 정규화 과정을 거침.

학습과 검증을 분리해야하기 때문에 60,000개의 학습 데이터 중 55,000개를 학습 시키고 5,000개를 검증 용으로 사용함<br>
분할에 시드가 지정된 `torch.Generator`를 사용해 반복 실행 시 같은 분할 결과를 얻도ㄹ.



## 3. 모델 구조

입력층 1개, 은닉층 2개, 출력층 1개로 구성

input Layer: 784 => hidden Layer1: 256<br>
hidden Layer1: 256 => hidden Layer2: 128<br>
hidden Layer2: 128 => output Layer: 10<br>


`view(x.size(0), -1)`은 이미지 픽셀을 1차원 벡터로 펼쳐서 `[batch, 784]`로 만든다.<br>
==> flatten() 기능


은닉층 뒤에는 ReLU 활성화 함수와 Dropout을 적용함.<br>
- ReLU: 음수를 0으로 바꾸어 비선형성을 제공
- Dropout 비율 0.2: 학습 중 일부 출력을 무작위로 0으로 만들어 특정 뉴런에 지나치게 의존하는 현상을 완화. <br>

*평가 모드에서는 Dropout이 비활성화된다.

출력층은 숫자 클래스마다 점수 10개를 반환.<br> `CrossEntropyLoss`가 내부적으로 분류에 필요한 정규화 계산을 수행하므로 출력층 뒤에 별도의 softmax를 적용하지 않음.

모델의 학습 가능한 파라미터 수는 다음과 같이 총 235,146개이다.

- 784 → 256: `784 × 256 + 256 = 200,960`
- 256 → 128: `256 × 128 + 128 = 32,896`
- 128 → 10: `128 × 10 + 10 = 1,290`

각 식에서 뒤에 더한 값은 각 층의 bias 파라미터 수이다.

## 4. 학습 설정

분류 손실 함수로 `nn.CrossEntropyLoss()`를 사용.<br> 모델의 클래스별 logits와 정수 형태의 정답 라벨(0~9)을 비교해 손실을 계산

- 알고리즘: Adam
- 초기 학습률: 0.001

학습률은 파라미터 갱신 크기를 조절한다. 
너무 크면 학습이 불안정해질 수 있고, 너무 작으면 학습이 느려질 수 있다.(실험 조건 1 참고)

`StepLR` 스케줄러: 5 epoch마다 학습률에 0.5를 곱하도록 설정됨. 


학습 함수는 각 epoch마다 다음 과정을 수행한다.

1. `model.train()`으로 모델을 학습 모드로 전환한다.
2. batch의 이미지와 라벨을 선택된 CPU 또는 GPU 장치로 이동한다.
3. 모델의 순전파 결과를 계산하고 손실을 구한다.
4. `optimizer.zero_grad()`로 이전 batch의 기울기를 초기화한다.
5. `loss.backward()`로 역전파하여 각 파라미터의 기울기를 계산한다.
6. `optimizer.step()`으로 가중치와 편향을 갱신한다.
7. 예측과 정답을 비교해 학습 Loss와 Accuracy를 집계한다.

학습 Loss는 batch 평균을 단순 평균하지 않고 `loss.item() * batch 샘플 수`를 누적한 뒤 전체 샘플 수로 나눈다. 마지막 batch가 다른 batch보다 작을 수 있기 때문에 이 방식이 샘플별 평균을 더 정확하게 계산한다.

학습 Accuracy는 정답을 맞힌 샘플 수를 전체 샘플 수로 나눈 뒤 100을 곱해 백분율로 표시한다.

## 5. 검증 및 최적 모델 선택

검증 함수는 `model.eval()`을 호출해 평가 모드로 전환하고, `torch.no_grad()` 블록 안에서 추론한다. 평가 단계에서는 파라미터를 갱신하지 않으므로 기울기 계산을 생략해 메모리와 연산을 절약한다.

각 epoch가 끝날 때 검증 Loss와 Accuracy를 계산해 출력하고 기록한다. 현재까지의 최저 검증 Loss보다 더 낮은 값이 나오면 해당 epoch 번호와 모델의 `state_dict`를 깊은 복사해 저장한다. 학습이 끝난 뒤 저장한 파라미터를 다시 불러오므로, 마지막 epoch 모델이 아니라 검증 Loss가 가장 낮았던 모델을 최종 평가에 사용한다.

## 6. 테스트 평가

학습과 검증 기반 모델 선택이 모두 끝난 뒤, 선택된 모델을 테스트 데이터에 한 번 평가한다. 테스트 데이터는 매 epoch의 모델 선택에 사용하지 않으므로 최종 성능을 독립적으로 확인할 수 있다.

프로그램은 다음 항목을 출력한다.

- `Final Test Loss`: 테스트 데이터 전체의 평균 손실
- `Final Test Accuracy`: 테스트 데이터에서 맞힌 비율(백분율)

실제 측정 결과는 코드를 실행한 뒤 아래 표에 기록한다. 실행 전에는 수치를 임의로 기입하지 않는다.

## 8. 오분류 사례 분석

테스트 평가 함수는 모든 테스트 샘플의 예측값과 실제 정답을 보관한다. 두 값이 다른 샘플의 위치를 찾아 오분류 개수를 출력하고, 실제 숫자와 예측 숫자 조합별 혼동 횟수를 집계한다.

혼동 횟수는 10×10 배열에 저장한다. 행은 실제 정답, 열은 예측값이다. 예를 들어 `confusion[3, 5]`는 실제 숫자가 3인 이미지를 5로 예측한 횟수이다. 코드에서는 오분류 중 가장 자주 나타난 숫자 쌍 최대 5개를 출력하고, 최대 10개의 오분류 이미지를 그림으로 표시한다. 각 이미지에는 정답(`True`)과 예측(`Pred`)이 함께 표시된다.

혼동 횟수와 이미지 사례는 어떤 숫자 쌍에서 실수가 자주 발생했는지 보여준다. 다만 코드가 원인을 자동으로 판정하는 것은 아니다. 실제 원인 분석은 표시된 이미지를 확인해 획의 모양, 필기체의 유사성, 이미지의 선명도 등을 근거로 작성해야 한다.

| 분석 항목 | 실행 결과 및 관찰 |
|---|---|
| 오분류 개수 | 실행 후 기입 |
| 가장 빈번한 실제 정답 → 예측 조합 | 실행 후 기입 |
| 이미지에서 관찰한 오분류 원인 | 이미지 확인 후 기입 |

Q. 128 -> 256에서는 왜 시간이 비슷할까?<br><Br>
A. batch size를 증가시키면 처리 횟수는 줄어들지만 이를 학습 시간도 줄어든다고 생각하면 안됨. 왜냐면 처리 횟수가 줄어드는만큼 이미지와 계산량이 늘어나기 때문. 따라서 하드웨어가 batch를 효율적으로 처리할 수 있는 batch size 최적값이 노트북에 따라 다르다고 생각됨.<br><Br>
-> Q. 그러면 64 -> 128에서는 왜 시간이 줄었는가? <br><br>
A. 128까지는 노트북이 효율적으로 학습 데이터를 처리할 수 있을 정도의 양이 였기 때문. 64는 노트북의 효율을 제대로 뽑아내지 못해 느렸던 것이라고 생각됨.
