# MNIST 숫자 분류 MLP 코드 설명 보고서

## 1. 과제 개요

과제: PyTorch를 이용해 MLP 구성하여 0부터 9까지의 손글씨 숫자 분류기 구현

구현에는 데이터 준비, 학습,검증,테스트 데이터 분리, MLP 구성, 미니배치 학습, 검증에 따른 모델 선택, 최종 테스트 평가 순서로 작동

## 2. 데이터 준비 및 분할

`torchvision.datasets.MNIST`로 공식 MNIST 데이터셋을 불러옴.

`transforms.ToTensor()`는 픽셀 범위를 일반적으로 0-255에서 0-1로 변환하는 정규화 과정을 거침.

학습과 검증을 분리해야하기 때문에 60,000개의 학습 데이터 중 55,000개를 학습 시키고 5,000개를 검증 용으로 사용함<br>
분할에 시드가 지정된 `torch.Generator`를 사용해 반복 실행 시 같은 분할 결과를 얻도ㄹ.



## 3. 모델 구조

입력층 1개, 은닉층 2개, 출력층 1개로 구성

input Layer: 784 => hidden Layer1: 256<br>
hidden Layer1: 256 => hidden Layer2: 128<br>
hidden Layer2: 128 => output Layer: 10<br>


`view(x.size(0), -1)`은 이미지 픽셀을 1차원 벡터로 펼쳐서 `[batch, 784]`로 만든다.<br>
==> flatten() 기능


은닉층 뒤에는 ReLU 활성화 함수와 Dropout을 적용함.<br>
- ReLU: 음수를 0으로 바꾸어 비선형성을 제공
- Dropout 비율 0.2: 학습 중 일부 출력을 무작위로 0으로 만들어 특정 뉴런에 지나치게 의존하는 현상을 완화. <br>

*평가 모드에서는 Dropout이 비활성화된다.

출력층은 숫자 클래스마다 점수 10개를 반환.<br> `CrossEntropyLoss`가 내부적으로 분류에 필요한 정규화 계산을 수행하므로 출력층 뒤에 별도의 softmax를 적용하지 않음.

모델의 학습 가능한 파라미터 수는 다음과 같이 총 235,146개이다.

- 784 → 256: `784 × 256 + 256 = 200,960`
- 256 → 128: `256 × 128 + 128 = 32,896`
- 128 → 10: `128 × 10 + 10 = 1,290`

각 식에서 뒤에 더한 값은 각 층의 bias 파라미터 수이다.

**[구현 중 생긴 궁금증]** <br><br>
**Q. 이미지 픽셀마다 위치가 정해져있을텐데 얘를 1차원으로 풀어버리면(flatten하면) 각각 위치는 어떻게 기억하지?**

A. 각 뉴련마다 가중치를 가지는데 뉴런의 가중치들을 다시 28X28로 배열하면 그 뉴런이 이미지의 어느 위치에서 민감한지 시각화할 수 있고 위치를 알 수 있게 됨. 

**->Q. 그러면 맨 처음 가중치 설정은 모든 뉴런이 똑같은 가중치 값을 가지나?**

A. 아님. nn.Linear()는 기본적으로 가중치와 편향 값을 작은 범위의 무작위 값에서 초기화하기 때문에 랜덤한 값을 가지게 됨. 

**->->Q. 각 뉴런의 픽셀값(0~1)에 따라 가중치를 차이를 두고 학습을 시키면 더 빨리 학습되는거 아닌가?(예를들어 픽셀값이 높은 뉴런의 가중치를 더 높게)**

A. 그렇다고해서 항상 더 빨리 학습되는 것은 아님. 왜냐면 밝기(픽셀값)만 보고 가중치를 미리 높여버리면 필요없는 픽셀의 영향까지 오히려 더 커질 수 있어 학습에 방해될 수 있다. 


## 4. 학습 설정

분류 손실 함수로 `nn.CrossEntropyLoss()`를 사용.<br> 모델의 클래스별 logits와 정수 형태의 정답 라벨(0~9)을 비교해 손실을 계산

- 알고리즘: Adam
- 초기 학습률: 0.001

학습률은 파라미터 갱신 크기를 조절한다. 
너무 크면 학습이 불안정해질 수 있고, 너무 작으면 학습이 느려질 수 있다.(실험 조건 1 참고)

`StepLR` 스케줄러: 5 epoch마다 학습률에 0.5를 곱하도록 설정됨. 


학습 함수는 각 epoch마다 다음 과정을 수행한다.

1. `model.train()`으로 모델을 학습 모드로 전환한다.
2. batch의 이미지와 라벨을 선택된 CPU 또는 GPU 장치로 이동한다.
3. 모델의 순전파 결과를 계산하고 손실을 구한다.
4. `optimizer.zero_grad()`로 이전 batch의 기울기를 초기화한다.
5. `loss.backward()`로 역전파하여 각 파라미터의 기울기를 계산한다.
6. `optimizer.step()`으로 가중치와 편향을 갱신한다.
7. 예측과 정답을 비교해 학습 Loss와 Accuracy를 집계한다.

학습 Loss는 batch 평균을 단순 평균하지 않고 `loss.item() * batch 샘플 수`를 누적한 뒤 전체 샘플 수로 나눈다. 마지막 batch가 다른 batch보다 작을 수 있기 때문에 이 방식이 샘플별 평균을 더 정확하게 계산한다.

학습 Accuracy는 정답을 맞힌 샘플 수를 전체 샘플 수로 나눈 뒤 100을 곱해 백분율로 표시한다.

**[구현 중 생긴 궁금증]**

**Q. epoch가 증가함에 따라 학습률을 왜 줄여줘야하는가?** 

A. 학습을 진행할수록 점차 최저점으로 다가가게 되는데 최저점에 가까이 갔을 때는 미세하게 조절해야 최저점을 찾을 수 있음<br>(예를 들어 단진자 운동을 생각하면 점점 갈수록 흔들리는 정도가 줄어들어야 최저점으로 감)<br>
이때 흔들리는 정도를 학습률이라고 생각하면 점점 갈수록 학습률을 줄여줘야 최저점을 찾을 수 있게되기 때문에 학습률을 줄여줘야함

## 5. 검증 및 최적 모델 선택

검증 함수는 `model.eval()`을 호출해 평가 모드로 전환<br>
`torch.no_grad()` 블록 안에서 추론.<br>
평가 단계에서는 파라미터를 갱신하지 않으므로 기울기 계산을 생략해 메모리와 연산을 절약함 

각 epoch가 끝날 때 검증 Loss와 Accuracy를 계산해 출력하고 기록함.<br> 현재까지의 최저 검증 Loss보다 더 낮은 값이 나오면 해당 epoch 번호와 모델의 `state_dict`를 깊은 복사해 저장함.<br>
학습이 끝난 뒤 저장한 파라미터를 다시 불러오므로, 마지막 epoch 모델이 아니라 검증 Loss가 가장 낮았던 모델을 최종 평가에 사용함. 

## 6. 테스트 평가

학습과 검증 기반 모델 선택이 모두 끝난 뒤, 선택된 모델을 테스트 데이터에 한 번 평가한다. 테스트 데이터는 매 epoch의 모델 선택에 사용하지 않으므로 최종 성능을 독립적으로 확인할 수 있음. 

프로그램은 다음 항목을 출력한다.

- `Final Test Loss`: 테스트 데이터 전체의 평균 손실
- `Final Test Accuracy`: 테스트 데이터에서 맞힌 비율

실제 측정 결과는 코드를 실행한 뒤 아래 표에 기록. 실행 전에는 수치를 임의로 기입하지 않음.

- 선택된 최적 epoch => 실행 후 기입 <br>
- 최적 검증 Loss => 실행 후 기입 <Br>
- 최종 테스트 Loss => 실행 후 기입 <br>
- 최종 테스트 Accuracy => 실행 후 기입 

## 7. epoch별 결과 및 그래프

각 epoch의 학습 Loss와 Accuracy, 검증 Loss와 Accuracy를 터미널에 출력 후 리스트에 저장.<br>
이후 Matplotlib으로 다음 두 그래프를 표시한다.

- 학습 Loss와 검증 Loss의 epoch별 변화
- 학습 Accuracy와 검증 Accuracy의 epoch별 변화

학습 Loss는 감소하지만 검증 Loss가 증가하는 현상이 지속되면 과적합 가능성을 의심할 수 있음. 
<br>학습과 검증 성능의 간격이 커지는지도 함께 살펴봄.

실행 결과를 보고서에 첨부할 때는 프로그램이 출력한 epoch별 수치를 표로 정리하거나 그래프 화면을 캡처해 추가함.
